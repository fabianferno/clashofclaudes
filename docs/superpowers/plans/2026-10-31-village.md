# Clash of Claudes — Plan 2: Village Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Plan 1's plain sidebar UI with the isometric village. It covers:
- compounds per workspace, structures per live session, and builders who walk and build;
- placement, drag-to-move and wall expansion;
- XP and house levels;
- a camera, a HUD with a builders bar, and restyled panels;
- the Plan 1 follow-ups that must land now;
- a debug-only test driver so the GUI can be checked without the owner.

**Architecture:**
- **Rust stays the single source of truth** for sessions, and now also owns XP, levels, stats and the persisted village layout (compound rects, house and structure tiles).
- **Layout algorithms are pure TypeScript** (placement, expansion, relocation, move validation). They run in the frontend, which then persists their results through two Rust commands.
- **The village is a PixiJS v8 canvas.**
  - Every entity is drawn by one replaceable Canvas2D function (ported from the mockup) into a cached texture, so frames only move sprites.
  - React renders the HUD and the right-side panels over the canvas.
- **The debug test driver** is a localhost-only HTTP endpoint in debug builds. It evaluates JS in the webview and returns the result (including PNG snapshots of the village canvas), so the controller can verify each visual task itself.

**Tech Stack:**
- Everything from Plan 1: Tauri 2, Rust, React 19 + TypeScript + Vite, zustand, xterm.js, vitest.
- New: **pixi.js 8.x** (latest 8.x at install time) and **@fontsource/lilita-one** (OFL, bundled locally).

**Spec:** `docs/superpowers/specs/2026-10-30-clashofclaudes-design.md`
- Sections implemented here: §2.5, 2.7, 2.11; §4 anti-goals; §5.1–5.6; §6.1 PixiJS; §7 village budgets; §9 art seam.
- Visual reference: `docs/mockups/village-v6.html`. Where the mockup and the spec disagree, the spec wins. In particular, all structures are one size; the mockup's TIERS table is dead.

**Carried in:** `docs/superpowers/plans/2026-10-30-core-sessions-followups.md` → "Must land before or with Plan 2", plus "Found in the owner GUI run".

**Roadmap after this:** Plan 3 covers the Codex, Gemini CLI and OpenCode adapters, notifications and the dock badge, first-run experience, signing, notarization, the DMG and the updater.

## Global Constraints

- **Everything from Plan 1's Global Constraints still holds:**
  - No network calls; localhost only, with tokens.
  - Never write to `~/.claude` or any project `.claude/`.
  - User strings are passed as argv elements.
  - Scrollback cap 2 MiB per session; 16 ms output batching.
  - Atomic `state.json`.
- **Art is original.** No Supercell art, names, UI or layouts. Font: Lilita One (bundled, OFL). White text with heavy dark outline `#1d130b`.
- **Isometric 2:1 tiles:** `TW = 64`, `TH = 32`, with `iso(x, y) = { x: (x - y) * TW / 2, y: (x + y) * TH / 2 }`.
- **Footprints:** main house **3×3** tiles, structure **2×2** tiles. All structures are the same size.
- **Agent palette** (outfit and roof), copied from the mockup's `TYPES`:
  - claude: body `#d97757`, roof `#d4683f`, wall `#f3e2c4`
  - codex: body `#3a3a40`, roof `#4a4d57`, wall `#cfccc5`
  - gemini: body `#4f7cf0`, roof `#4f7cf0`, wall `#eef1f8`
  - opencode: body `#33a889`, roof `#2f9a7e`, wall `#dcbf92`
  - custom: body `#8d8a83`, roof `#7d7a74`, wall `#e4ded2`
- **State colors:** working `#f5a623`, needs `#ff4b3e`, stuck `#8e8e8e`, finished `#ffcf33`, idle `#4ab0f0`.
- **Class = model tier:** Apprentice / Craftsman / Master.
  - Claude: `haiku` → Apprentice, `sonnet` → Craftsman, `opus` → Master, `fable` → Master.
  - Any agent with one model or an unknown model → Craftsman.
  - The mapping is a config table, not code branches.
- **Gear = effort** (Claude has 5 levels; ruling R2):

  | Effort | Hammer | Stars |
  |---|---|---|
  | `low` | Wooden | ★ |
  | `medium` | Iron | ★★ |
  | `high` | Gold | ★★★ |
  | `xhigh` | Runed | ★★★★ |
  | `max` | Enchanted, glowing | ★★★★ |

  An agent without effort support shows the effort recorded on the builder.
- **XP:** a flat **100 XP** per closed session that reached Finished and is not Stuck. XP to go from level L to L+1 is `round(100 × 1.4^(L−1))`, so 100, 140, 196, 274, 384, … Model and effort never change XP (anti-goal §4).
- **Village level** = total shipped sessions (closed after Finished), across all workspaces.
- **Performance:**
  - ≤ 30 fps when focused, ≤ 15 fps when not focused, rendering stopped when hidden or minimized.
  - Ground and forest baked into one texture, re-baked only when the layout changes.
  - No per-frame Canvas2D drawing; only sprite transforms.
- **No fake data:** no progress percentages. Scaffolding height is `0.92 × (1 − e^(−steps/12))`, a curve that never reaches full height. Show elapsed time and step count. Hide tokens (no adapter reports them yet).
- **The game never blocks:** the agent process starts before any walk animation. Every village element is at most one click from its terminal. There are no tutorials.
- **Debug driver:**
  - Compiled into debug builds only (`#[cfg(debug_assertions)]`), and only started when the env var `COC_DRIVER=1` is set.
  - Binds `127.0.0.1` on an OS-assigned port and needs a random token.
  - Release builds contain no driver server. The `driver_result` command exists in release but always returns `Err("driver disabled")`.

### Task 4: Pure layout engine (TypeScript)

**Files:**
- Create: `src/village/iso.ts`, `src/village/layout.ts`
- Test: `src/village/iso.test.ts`, `src/village/layout.test.ts`

**Interfaces:**
- `iso.ts`:
  - `TW = 64`, `TH = 32`
  - `iso(x: number, y: number): {x: number; y: number}`
  - `toGrid(wx: number, wy: number): {x: number; y: number}`, the inverse of `iso`
- `layout.ts`. Rects are in tiles, half-open: `[x0, x0+w) × [y0, y0+h)`.
  ```ts
  export interface Rect { x0: number; y0: number; w: number; h: number }
  export const HALL: Rect = { x0: -2, y0: -2, w: 5, h: 5 };
  export const GAP = 4;            // min tiles between compound walls and anything else (roads)
  export const START = 7;          // new compound interior is 7×7
  export const GROW = 3;           // expansion step
  export const HOUSE = 3, STRUCT = 2;
  export function wallRect(c: Compound): Rect;                 // interior grown by 1 on each side
  export function placeCompound(existing: Compound[]): Compound; // nearest free area around HALL; house in the interior corner nearest HALL
  export function findSpot(c: Compound, taken: Tile[]): Tile | null; // nearest to house centre; prefers a 1-tile gap around all occupants
  export function expand(c: Compound, all: Compound[]): { compound: Compound; shift: Tile }; // grows by GROW away from HALL, alternating w/h (w first when w<=h); tries the other side on collision; else relocates — shift is the translation applied to house/spots
  export function canPlace(c: Compound, taken: Tile[], at: Tile, size: number): boolean; // inside interior, no overlap
  export function spotFor(c: Compound, all: Compound[], taken: Tile[]): { compound: Compound; spot: Tile; expanded: boolean; shift: Tile };
  export function gateSide(c: Compound): 'n' | 's' | 'e' | 'w'; // the wall side facing HALL
  ```
  - `taken` holds the top-left tiles of 2×2 structures. The house is always an occupant.
  - Every result keeps `wallRect`s apart by at least `GAP` from each other and from `HALL`.

- [ ] **Step 1: Failing tests**
  - `iso_round_trip`: for 20 random points, `toGrid(iso(p)) ≈ p` (to 1e-9).
  - `first_compound_is_near_hall_and_clear`: `placeCompound([])`:
    - `w == h == 7`
    - the distance from `wallRect` to `HALL` is ≥ `GAP`
    - the house lies inside the interior, in the corner nearest the hall
  - `eight_compounds_never_overlap`: place 8 in sequence. All pairwise wall rects are ≥ `GAP` apart and ≥ `GAP` from `HALL`.
  - `find_spot_prefers_gap_then_packs`: fill a 7×7 compound. The first 2 spots keep a 1-tile gap. Then it packs. When full it returns `null`.
  - `twelve_sessions_expand_without_collision`: with 4 compounds placed, call `spotFor` 12 times on one of them, accumulating spots. All spots are inside, none overlap each other or the house, and the compounds still keep `GAP`. `expanded` is true at least once.
  - `expand_prefers_away_from_hall_and_alternates`: compound east of the hall. The first expand grows `w` by 3 on the east side (`x0` unchanged). The second grows `h`.
  - `expand_relocates_when_blocked`: surround a compound on both growth sides. `expand` returns a non-zero `shift`, and the result is collision-free.

## Rulings made while planning (check these)

- **R1:** The layout algorithm lives in TypeScript, and Rust persists its results (`set_compound`, `set_session_spot`).
  - Why: it's pure geometry that the scene needs every frame, and Rust stays the authority for sessions, XP and stats.
  - Cost if wrong: two concurrent starts could race for one spot. Mitigation: the store serializes `ensureSpot` calls through a promise chain.
- **R2:** The 5 Claude effort levels map to 5 hammers. xhigh gets a new "Runed" hammer with ★★★★, and max keeps ★★★★ plus the glow, as the spec says.
  - Cost if wrong: the art for one hammer.
- **R3:** Fable maps to Master.
- **R4:** XP 100 per session; curve ×1.4 per level.
- **R5:** Compounds start with a 7×7 interior and grow by 3. Compounds keep 4 tiles of road from each other and from the hall.
- **R6:** "Open in editor" tries `code`, then `cursor`, then the system opener. A setting is Plan 3.
- **R7:** "Pop out" is an in-window full-size overlay, not a second native window (cheaper, and only one xterm per session).
- **R8:** "Shipped today" uses local midnight; tokens are hidden.
- **R9:** The trust menu's Deny accepts "No, exit", so Claude quits and the session ends Stuck or Ended.
